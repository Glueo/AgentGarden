# 2026–2027 Agent 实习准备计划

目标：面向 2027 年暑期 Agent 应用研发、Agent Harness/评测和 AI 应用后端实习，在课业、导师任务、健身和生活存在波动时，仍能持续建立算法、Agent 工程、项目表达与求职能力。

相关训练：[[算法复习]]。

## 计划定位

这不是要求逐周完全执行的全覆盖路线图，而是一套滚动执行系统：

- 保留从 Agent Loop、工具、Coding Loop、Trace、Eval 到作品集和面试的能力结构；
- 降低周计划刚性，只对近期窗口作出承诺；
- 远期内容按真实课表、导师工作量、算法状态、项目 Gate 和招聘反馈重排；
- 完成保底周即视为成功，不通过下周加倍来偿还历史欠账。

## 周负荷

| 周类型 | 总投入 | 建议分配 | 使用规则 |
|---|---:|---|---|
| 期末/低能量周 | 4–6h | 算法 2h；项目维护或复盘 1–2h | 其余主动延期，不记失败 |
| 保底周 | 8–10h | 算法 4h；项目/LLM 3–4h；求职与复盘 1–2h | 完成即视为本周成功 |
| 理想周 | 12–14h | 算法 5–6h；项目 4–5h；LLM/CS/八股 1–2h；求职与复盘约 1h | 是状态良好时的上限，不是每周指标 |
| 冲刺周 | 16–18h | 围绕一个明确交付物临时加量 | 只用于寒假、作品集收尾、真实面试或明确空闲周；不得连续，也不得补债 |

全周期理想预算按 **500–550 小时**理解；529 小时只是当前估算，不作为精确完成指标。

### 未完成事项处理

未完成内容不自动形成必须偿还的欠账。周复盘时只允许：

1. 删除；
2. 延期；
3. 重新排期。

只有仍对下一个 Gate 有直接价值的事项才进入 Backlog；不得因为上周未完成而在下周加倍。

## 主项目：可信 Coding Agent Harness

服务对象：需要理解和修复小型 Python 仓库 Issue 的开发者。

核心流程：

> Issue → 搜索证据 → 修改计划 → Patch 预览 → 人工批准 → 应用 Patch → 测试 → 读取反馈 → 再修改

### A. 核心必做

目标是在 2027 年 2 月前形成可投递版本：

- CLI；
- 单 Agent Loop；
- 文件读取和文件搜索；
- Patch 生成、预览与批准后受控应用；
- 测试执行；
- 未经人工批准不得写文件；
- JSONL Trace；
- 20–30 条自建 case；
- 任务成功率、失败分类和平均步骤数；
- README；
- CLI 本地一键运行；Docker 只在环境复现确有需要时使用。

### B. 有余力再做

- 本地代码检索或轻量 RAG；
- SQLite Session；
- checkpoint/replay；
- token/成本监控；
- 40–50 条 case；
- 细粒度权限策略；
- FastAPI。

### C. 默认删除

- Multi-Agent 对照；
- MCP Server / Skill 封装；
- Browser/UI 和完整前端；
- 强制开源 Issue/PR；
- 复杂异步、队列与分布式部署；
- 把视频和博客作为项目功能 Gate。

项目的价值来自可验证的 Coding Loop、Trace、Eval 和失败分析，而不是功能数量。

## 能力 Gate

Gate 只控制是否增加项目范围，不阻塞算法、课程和正常生活。错过推荐窗口时先缩小范围；未通过当前 Gate 时不增加新框架。

| Gate | 推荐 / 最晚窗口 | 能力门 | 通过标准 |
|---|---|---|---|
| Gate 0 | 9 月上旬 / 9 月 13 日 | 启动准备 | 本地环境、一页 Spec、固定时间块、9–10 月最小执行规则；不要求公开仓库或完整看板 |
| Gate 1 | 10 月中旬 / 11 月上旬 | 最小 Agent | 单 Agent Loop、至少一个工具、JSONL Trace、10 条 case；失败可读 |
| Gate 2 | 11 月中旬 / 12 月中旬 | 工具与审批 | Tool Registry、Trace、Patch 预览和人工审批；不强制 RAG/Memory 同期完成 |
| Gate 3 | 12 月中旬 / 1 月底 | 最小 Coding Loop | Issue→证据→计划→批准→Patch→Test 闭环；15–20 条 case 有真实结果 |
| Gate 4 | 1 月下旬 / 2 月 14 日 | 可运行、可评测 | 20–30 条 Eval、失败分类、README、CLI 本地启动；Docker 仅按需 |
| Gate 5 | 2 月底 / 3 月中旬 | 可讲、可投递 | 简历项目描述、5 分钟讲稿、最简 Demo；视频/博客不是前置条件 |
| Gate 6 | 3 月 / 4 月底 | 反馈驱动补缺 | 只根据真实 JD、笔试或面试反馈补一个最高价值缺口 |

到 2027 年 6 月的结果采用情景表达：有暑期 Offer，或者形成“持续投递 + 日常实习/实验室/项目”的明确备选路径。Offer 不是可控的能力 Gate。

## 当前承诺：P0–W06

当前只承诺 2026-08-27 至 2026-10-25，共 **82 小时**。W07–W41 只保留为能力地图和候选路线，2026 年 10 月底再重排。

| 周 | 计划 | 项目主线 | 算法主线 | 关键产出 |
|---|---:|---|---|---|
| P0 | 5h | 确认项目问题与用户 | 复写 2 道旧题，标红黄绿 | 项目问题草案 + 算法基线 |
| P1 | 6h | 一页 Spec | 数组、二分、双指针 2–3 题次 | Spec v0.1 + 8–10 个 JD 技能词 |
| P2 | 4h | 环境检查与最小执行规则 | 复写 1–2 道红黄题 | Gate 0 |
| W01 | 10h | Agent/Workflow 边界与最小流程 | 数组、二分、滑窗 4–6 题次 | 一页问题定义 + 最小流程 |
| W02 | 11h | 可测试的结构化输出实验 | 数组综合、前缀和、矩阵 4–6 题次 | 可重复结构化输出 |
| W03 | 11h | 最小 Loop + 一个工具 | 链表 4–6 题次 | 最小 Agent v0.1 |
| W04 | 12h | Tool Registry、Trace、累计 10 cases | 哈希 4–6 题次 | Gate 1 候选 |
| W05 | 11h | Trace、Context 与证据组织 | 字符串、双指针 4–6 题次 | 可解释的上下文结构 |
| W06 | 12h | 代码检索/RAG Spike；无收益则继续完善 Loop | 栈、队列 4–6 题次 | 10 月复盘与后续重排输入 |

W01–W06 的理想分配以算法恢复优先：算法约 5–6 小时、项目 3–4 小时、基础与复盘 1–2 小时。题次只是参考，小时、重写质量和题型识别更重要。

## 算法路线

- **2026 年 9–12 月**：代码随想录高频核心专题。优先数组、链表、哈希、二分、双指针、滑动窗口、栈队列和树；每周 4–6 题次，红黄题重写计入。
- **2027 年 1–2 月**：补回溯、贪心、动态规划和图，开始 Hot100 迁移；每周 6–8 题次。
- **2027 年 3 月起**：每周一次计时练习，关注正确率、编码速度、边界和思路表达，不继续追求题量堆积。
- 低能量周只完成两道题也可以，只要进行了重写和极简复盘。

单题复盘与题目记录继续维护在 [[算法复习]]。

## CS 与求职优先级

- 2026 年 9–10 月只保留 Python、Git、Linux、HTTP，并按项目需要学习；
- OS、网络深入、MySQL 和 Redis 从 11 月后根据项目、JD、笔试和面试反馈分批补；
- 2027 年 3 月起，优先级依次是投递/笔试/面试、算法计时、项目讲解与真实问题修复、八股口述；
- 只有多个真实 JD 或面试反馈反复暴露同一缺口时，才为项目增加新功能。

## 过载删减顺序

依次删除：

1. Multi-Agent、Browser/UI、MCP、复杂部署；
2. 新框架阅读和非关键 CS 八股；
3. 非关键项目功能、额外实验、博客和视频；
4. 额外投递整理与形式化文档。

保底不可删：

- 每周 2–4 小时算法；
- 主项目一个最小闭环的维护或推进；
- 每周 15–30 分钟复盘；
- 睡眠、健身、课程和真实导师任务。

权限细化、Eval 扩充和 README 是项目发布前不可删，但项目前期可以延后；它们不应增加前两个月的启动阻力。

## 滚动重排

2026 年 10 月底重排 W07 以后，只依据以下实际证据：

- 第一学期真实课表与期末安排；
- 导师任务的平均负荷和波动；
- W01–W06 的实际投入与完成率；
- 算法红黄题比例、独立完成时间和薄弱专题；
- Gate 1 是否通过；
- 代码检索/RAG Spike 是否产生可测收益；
- 当时有效 JD 的共同技能要求。

不得因为旧版周计划仍有内容，就把它当成历史欠账。
