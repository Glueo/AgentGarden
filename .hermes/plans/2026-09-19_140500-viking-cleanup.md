## 3. Architecture

先「备份 + 检索基线」，再「去 peer 分流」（配置 + garden 自动化代码，根因），随后「按类型删噪声内容」，再「审查白名单四类 + 收敛过时实体 + 删 acceptance + 合并旧 peer」，最后「回归验证」。所有数据操作走 `ov` CLI。

```python
def patch_env(path: Path, values: dict[str, str], remove: set[str] | None = None) -> None:
    existing = path.read_text(encoding="utf-8").splitlines() if path.exists() else []
    remove = remove or set()
    keys = set(values) | set(remove)
    kept = [line for line in existing if not any(line.startswith(f"{key}=") for key in keys)]
    kept.extend(f"{key}={value}" for key, value in values.items() if key not in remove)
    write_private(path, "\n".join(kept) + "\n")
```

**Task 3.2 逐类审查冗余与过时**

判定标准：
- **冗余**：同一事实在多个文件/多个 URI 重复（含 peer 侧 `preferences/` 的 ~25 个 `mem_*.md` 与 user 侧重复）。
- **过时**：无日期的「当前状态」表述（如路由、PID、版本、Dreamer 状态）已与实时不符。

**审查对象（已核实的结构）：**

| 位置 | 内容 |
|---|---|

| `preferences/Glueo/`、`preferences/gwen/` | 沟通/设计偏好，含重复候选 |

| `peers/hermes/memories/preferences/` 的 `mem_*.md` | 旧 peer 侧偏好，与 user 侧重复候选 |

**Task 3.3 清理动作（产出清单，不自动删）**

- 冗余：合并互补信息到单一文件后删副本；冲突以用户明确表达为准，证据不足留标记。
- 过时：无日期「现状」改写为带日期事件，或删除。
